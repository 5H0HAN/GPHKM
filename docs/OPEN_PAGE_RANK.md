# Open PageRank provider boundary

Set `OPEN_PAGE_RANK_API_KEY` only in the private server environment or deployment secret store. Use a current Open PageRank key from Keywords Everywhere; legacy DomCop keys were retired. Do not paste keys into source, browser configuration, logs, or this document.

`src/server/metrics/open-page-rank.ts` is an internal, server-only transport boundary. It accepts 1–100 bare DNS hostnames (including IDNs), trims whitespace, lowercases, removes a final dot, converts IDNs to ASCII, and rejects URLs, ports, credentials, IP literals, invalid labels, and reserved demo suffixes (`.example`, `.test`, `.invalid`, `.localhost`, `.local`) before provider requests. It sends unique hostnames to the fixed HTTPS endpoint with bearer authentication and `include_history: false`. Redirects are rejected, the whole fetch/body read has a 10-second timeout, and the decompressed response is capped at 256 KiB. It makes no domain/website fetch, logs nothing, and exposes generic transport errors.

The allowlisted result preserves the provider's two scopes. Root domains and `www` aliases use the registered-domain score; other queried subdomains use their exact `hosts[].open_page_rank` score and are stored/displayed with `HOST` scope. Each stored observation records both the provider's metric target and the exact listing hostname sent in the request. Approval and customer projection require that requested hostname to still match the listing URL; changing the website makes earlier observations stale and hides them until refreshed. This avoids showing one parent-domain score as the score for every hosted site under it or carrying a score over to a different website. A found score of zero remains available; not-found is null/missing. History, global rank and referring-domain counts remain omitted. Failed calls throw and never manufacture a zero.

The current implementation is a staff-triggered refresh in the staff metrics console. It checks the `metrics.refresh` permission, accepts 1–100 unique listing IDs, limits each staff account to five refresh batches in a rolling 24-hour period, records start/completion/failure audit events, and persists provider observations. The provider request runs outside retryable database transactions. Only Super Admin may append an approval/revocation event for the current available observation, with attribution text, a bounded rights-evidence reference, and review reason. This is an internal attestation only; it does not establish actual licensing or legal rights. L-05 remains the external customer-display gate. The server and database customer projections fail closed unless `GPHKM_METRIC_CUSTOMER_DISPLAY_L05_VERIFIED=true` is explicitly configured after L-05 review; keep it false until then. Every refresh writes a newer unapproved observation, so an older attestation does not expose stale data. This does not add Ahrefs or Moz support.

Contract checked against the official [API reference](https://keywordseverywhere.com/openpagerank/docs) and [OpenAPI specification](https://openpagerank.keywordseverywhere.com/v1/openapi.json) on 2026-10-28: `POST /v1/domains/bulk`, `Authorization: Bearer <key>`, JSON `{domains: string[], include_history: false}`; response `as_of`, `count`, `results[].domain`, `found`, and `open_page_rank` (0–10 or null). Current free-key policy requires a configured egress IPv4 address from 2026-11-01; consult the provider account/docs for current limits.

Run the isolated offline checks with Node 24+: `node --test tests/open-page-rank.test.mjs`. They use synthetic responses and never contact the provider or read a real key.
